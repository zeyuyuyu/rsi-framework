# Terminology (use these words and symbols in every figure)

| Term in the paper | Symbol | Meaning | Do not use |
|---|---|---|---|
| task instance / scene | c = (ℓ, x₀) | a language instruction ℓ and an initial configuration x₀ (object placements) | "state S" |
| policy (the **artifact**) | π_θ, θ | OpenVLA-OFT 7B with a LoRA adapter; maps instruction + camera/proprioception to action chunks | |
| training program (the **harness**) | P, space 𝒫 | how experience is collected (instances, K attempts, temperature T), which attempts become training data, how the policy is updated; stored as JSON | "recipe" in labels (the text uses "recipe" only informally), "program" alone |
| version | (θ, P) | a policy together with the program that trained it | |
| retained version | (θ*, P*) | the version the loop currently keeps; it starts the next round | "current", "best" |
| success rule | v(c, τ) ∈ {0, 1} | the task's fixed success check in the simulator; nothing in the loop can change it | "oracle", "verifier the policy cannot influence" |
| trajectory / attempt | τ | one rollout of the policy from x₀ | "sampled from π" |
| training block | | one pass of: sample instances, K rollouts each, label, select data, LoRA update (100 optimiser steps); 3 blocks per candidate | "training step", "inner step" |
| round | r | every candidate trains 3 blocks from θ*, then selection | |
| candidate | θ_i | a policy trained in this round under program P_i | |
| data recursion | | experience is generated by the current candidate (first block: θ*), so always by the latest policy | |
| frozen generator (`nonrec`) | θ₀ | control: experience always generated by the initial policy | |
| shuffled labels (`shuffled`) | | control: success labels permuted within each instance (keeps the count, breaks which attempt succeeded) | "no verifier" (ok in captions: "verifier removed") |
| gate / selecting policy updates | G_r | candidates and the parent scored on the same newly drawn validation instances (200 episodes, greedy); best candidate kept if ≥ parent | "paired evaluation: current vs candidates" |
| `nogate` | | control: every candidate accepted ("always accept") | |
| meta level / program adaptation | | a proposer edits P inside 𝒫; each proposed program trains a real candidate; a program is kept only with the candidate it trained | "recipe adaptation" |
| proposers | | `fixed` = adaptation off; `full` = numeric search; `llm` = language model (knob space); `llm_harness` = language model with a workspace (files, memory, tools) over the harness space | "Meta · Recipe Proposal" |
| knob space / harness space | | 10 hyperparameters / those plus 9 procedure components (policy-gradient ratio, loss aggregation, BC likelihood temperature, ...) | |
| one-shot RL (`onebig`) | R = 1 | the whole budget in one round of 18 blocks from the initial policy; also run with 36 blocks | "plain RL" is fine in text |
| audit | | 200 more episodes recorded for kept candidates, never used for any decision | |
| sealed tests | | official (50 fixed states per task, 500 episodes) and fresh (1,000 sampled placements never used anywhere); read once after every run ended | |
| counted tuning | | RL is charged its 21 pilot runs (213.4 GPU-hours) that chose its recipe | |
