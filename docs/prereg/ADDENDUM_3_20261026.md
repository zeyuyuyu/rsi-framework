# Addendum 3: longer-horizon test of recursion (exploratory; committed before any of its runs)

Written 2026-10-26 after the pre-registered 4-round C3 result on Qwen2.5-Coder-1.5B came in negative:
`fixed` - `nonrec` on CRUXEval-O = -0.58 points, 95% CI [-2.21, +1.08], seeds 1-3. That result stands as
"C3 not shown at 4 rounds" and is reported as such; nothing below changes it.

## Hypothesis

A frozen initial generator (`nonrec`) still supplies useful practice while the model is close to its starting
point. Recursion should only matter once the trained model has outgrown the initial model's proposals and
attempts: then `nonrec` plateaus while `fixed` keeps finding cases at its new frontier.

## Design

Same frozen seed program, gate/audit, tests and sandbox as the main study; only `engine.rounds` = 8.
Arms `fixed` and `nonrec`, seeds 1-3, Qwen2.5-Coder-1.5B-Instruct, Baidu AIHC (one card each; initial-model
scores are paired within each run, as for the other Baidu runs). Tests are read once after round 8 for every
accepted version, so the 4-round point of these runs is also reported.

## Readings (decided now)

* Recursion supported at long horizon: `fixed` - `nonrec` at the final version >= +1.0 point on CRUXEval-O,
  paired CI of the seed-averaged per-problem difference excludes 0, AND `nonrec` accepts fewer gate gains in
  rounds 5-8 than `fixed`, summed over seeds.
* Otherwise: "recursion not shown up to 8 rounds" -- the improvement in this domain comes from verified
  self-generated practice, not from the improved model generating the data.
* Either way the result is labelled exploratory (added after the 4-round C3 result was seen).
