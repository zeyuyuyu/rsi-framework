# Addendum 1 to pre-registration v2 (committed before any main run)

## What was observed on the development model (Qwen2.5-Coder-1.5B, seed 0)

Two development runs of the earlier single-level loop (SFT on verified self-traces vs the same loop on
unverified self-traces) and one one-round pilot of the two-level engine were evaluated on the test suites.
The pilot reading tests was unintended (the engine evaluated tests by default); its test numbers were not
used for any decision. All three are development runs and are **excluded from every claim**.

| run | gate/val (self-proposed) | CRUXEval-O | CRUXEval-I | LCB-exec |
| --- | --- | --- | --- | --- |
| verified, 3 rounds (2 accepted) | 42.75 -> 51.5 | 37.0 -> 39.25 (p=0.12) | 45.75 -> 46.9 | 30.9 -> 26.5 (CI excl. 0) |
| unverified control (1 accepted) | 42.75 -> 43.75 | 37.0 -> 38.1 | 45.75 -> 45.4 | 30.9 -> 25.7 (CI excl. 0) |

Manual inspection of the 63 LCB-exec problems the verified run lost: 59 are wrong values (not parse or
truncation failures; unparsed answers fell from 29 to 18). Traces increasingly summarise what the code
does instead of tracing it. Diagnosis: outcome-only verification admits lucky traces on short
self-proposed programs with low-entropy outputs (booleans, small ints), and a gate built from the same
self-proposed distribution rewards the same shortcut, so it cannot catch out-of-distribution regression.

## Changes made because of this (before any main run)

1. **Gate and audit sets now come from an external distribution**: MBPP problems (974 real programming
   problems; one execution case per problem from its first test call), executed by the sandbox for the
   label, near-duplicates of CRUXEval/LCB removed, split by hash: gate 489 / audit 472. Neither
   self-generated nor a test suite.
2. **Curation excludes cheap-to-guess answers by default** (`curation.exclude_flag = "guessable"`:
   booleans, None, ints in [-3, 3], empty containers). The flag is part of the improvement program and
   the meta level may switch it off.
3. Engine option `seal_tests` for pilots: development decisions read the gate only.
4. The seed program (SFT vs GRPO, with/without the guess filter) is chosen by two-round pilots on the
   development model using the MBPP gate only. The chosen program is then frozen for every model and arm.

## Unchanged

Claims C1-C4, their controls and bars, the test suites, the number of rounds and seeds. The development
model's claims will come only from fresh seeds run after the configuration is frozen.
