# Pre-registration v2: two-level RSI framework (rsi_two_level_v1)

Committed 2026-10-25, before any held-out test score of a trained version under this framework.
Supersedes `CODE_WM_PREREG_20261025.md` (single-level loop). Development decisions (seed program,
operator, budgets) may use **gate** scores only; the audit set and the test suites never inform them.

## Claim structure

The deliverable is the framework. Model gains are evidence for four separate claims, each with its own
control and its own bar; a claim that misses its bar is reported as not shown.

| Claim | Arm vs control (same model, seed, rounds) | What it shows |
| --- | --- | --- |
| C1 improvement | `full` final vs `initial` | the framework improves the model on held-out tests |
| C2 feedback | `fixed` vs `shuffled` (oracle labels permuted within each case) | external verification is the lever, not more fine-tuning |
| C3 recursion | `fixed` vs `nonrec` (frozen initial model generates every round's cases and attempts) | data generated by the improved model is what keeps improving it |
| C4 meta | `full` (self-edit proposer, 2 candidates/round) vs `fixed` (seed program, 1 candidate) | improving the improvement program adds to object-level RSI |

`full` costs more compute per round than `fixed`; GPU-seconds are logged for every run and C4 is also
reported per GPU-hour.

## Fixed protocol

* Rounds: 4. Gate 400 / audit 400 programs proposed by the initial model before training, never in the
  few-shot pool, registered as held-out for near-duplicate rejection (char-10-gram Jaccard >= 0.5).
* Acceptance: candidate gate >= parent gate. Program selection among candidates: best gate.
* Oracle: sandboxed interpreter; an attempt is verified iff its answer is a Python literal equal to the
  interpreter's value.
* Seed program: chosen from {SFT on verified traces, GRPO on mixed groups} by a one-round gate pilot on the
  development model (Qwen2.5-Coder-1.5B-Instruct); then frozen for all models.
* Tests (read once after the last round, for every accepted version): CRUXEval-O (primary, 800),
  CRUXEval-I (transfer, never trained on, 800), LiveCodeBench execution (479).
* Seeds: 3 per arm; the seed changes proposals, samples and training order.

## Bars (primary test CRUXEval-O; per model)

* C1: mean over seeds of (final - initial) >= +2.0 points; paired bootstrap 95% CI of the seed-averaged
  per-problem difference excludes 0; >= 2 of 3 seeds individually exclude 0.
* C2, C3, C4: mean arm difference >= +1.0 point with paired CI excluding 0 (per-problem, seed-averaged).
* Recursion evidence also requires: accepted gain in >= 2 rounds after round 1 for `full` or `fixed` in at
  least 2 of 3 seeds (gains are not a single jump).
* Overfitting check: audit-set change has the same sign as the gate-set change for accepted nodes; if not,
  the run is flagged and discussed.

## Models

Code world model domain: Qwen2.5-Coder-1.5B (development), Qwen2.5-Coder-7B, Qwen3-8B, Meta CWM 32B
(served as Llama for contexts < its 8192 sliding window), and one non-Qwen model. VLA domain (separate
pre-registration once its harness checks pass): OpenVLA-7B on LIBERO, official 50 init states x 10 tasks
as the test.

## Multi-angle verification required before any claim

1. Independent re-scoring of all test records by a second scorer written separately.
2. Blind external-model audit of sampled flips (initial wrong -> final right and reverse): reasoning vs
   format change; unparseable-answer rate per version.
3. Leakage audit of all admitted training programs against every held-out program.
4. Other models, other suites, data seeds.
